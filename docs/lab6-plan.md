# Лабораторная работа 6 — первая версия MVP

## Согласованный объём

Основной сценарий: открыть приложение → создать задачу с дисциплиной и сроком → найти её → изменить → завершить → обновить страницу и увидеть сохранённые данные → удалить после подтверждения.

Выбраны FR-02–06: CRUD задач, три статуса, поиск и совместные фильтры, сортировка, просрочка. Успех: все операции меняют список и переживают перезагрузку страницы; ошибочный ввод не сохраняется; отмена удаления ничего не меняет; сегодня и выполненные задачи не считаются просроченными.

Границы: один пользователь и один браузер. Авторизация, сервер, REST API, общая база, синхронизация, уведомления и роли не входят в эту версию. Данные хранятся в localStorage; при отказе записи интерфейс не сообщает об успехе и сохраняет ввод.

## Уточнения относительно полного ТЗ

Полное ТЗ описывает React, Django и PostgreSQL. Лабораторная №6 разрешает выбрать меньший сценарий без сервера и входа. Для этой итерации React + Vite обеспечивают запуск; localStorage заменяет серверное хранение. Это ограничение первой версии, а не реализация REST API или защиты данных разных пользователей.

Redux, Axios, Tailwind и Router пока не нужны: есть один экран, состояние принадлежит App, API отсутствует; существующие CSS из лабораторной №5 используются повторно. Добавлять их следует при появлении соответствующих функций. Пользователь согласовал продолжение проекта после предложенного плана; предыдущие лабораторные в tempPage сохраняются.

## Последовательные задания ИИ агенту

1. **Основа.** Контекст: репозиторий содержит HTML/CSS предыдущих работ. Добавить React + Vite, корневой index.html и команды dev/build. Ограничение: не менять tempPage. Приёмка: production сборка проходит, страница доступна.
2. **Данные.** После проверки основы добавить валидацию, localStorage и чистые функции фильтрации/сортировки/просрочки. Приёмка: тесты на неверную дату, пробелы, совместные условия, границы дат, ошибки и повреждённое хранилище.
3. **Действия.** После проверки данных собрать главный экран, форму создания/редактирования, статусы и подтверждение удаления. Ограничение: без backend и фиктивного входа. Приёмка: полный сценарий и перезагрузка, отмена удаления, пустые состояния.
4. **Проверка.** После проверки действий проверить клавиатуру, узкий/широкий экран, сообщения и консоль; записать фактические результаты, ограничения и исправления. Подготовить README и краткий отчёт; опубликовать логические коммиты.

Текущая работа использует ChatGPT/Codex. Предложения и принятые изменения фиксируются в отчёте по результатам фактических проверок.
