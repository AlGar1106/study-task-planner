# Backlog фронтенда

## FE-001 Подготовить структуру репозитория
Week: 1 · Epic: Подготовка · Priority: High · Estimate: 1 ч

Dependencies: нет

Description: Добавить README, Node .gitignore и папки src/app, pages, components, features и services. Реализацию React пока не начинать.

Acceptance Criteria: Папки и README есть в Git; node_modules и .env исключены; первый коммит начинается с chore.

## FE-002 Создать HTML структуру главной страницы
Week: 1 · Epic: Подготовка · Priority: High · Estimate: 2 ч

Dependencies: FE-001

Description: В tempPage/index.html разместить шапку, навигацию, поиск, фильтры и список учебных задач. Использовать семантические теги и минимальный CSS.

Acceptance Criteria: Файл открывается в браузере; один h1; у полей есть label; список состоит из article; нет декоративных эффектов.

## FE-003 Настроить React и Vite
Week: 1 · Epic: Основа интерфейса · Priority: High · Estimate: 2 ч

Dependencies: FE-002

Description: На следующем этапе установить React, Vite, React Router, Redux Toolkit, Axios и Tailwind. Добавить команды dev и build; временную HTML страницу оставить в tempPage.

Acceptance Criteria: npm install, npm run dev и npm run build проходят; версии зависимостей зафиксированы lock файлом.

## FE-004 Добавить страницы и маршруты
Week: 1 · Epic: Основа интерфейса · Priority: High · Estimate: 2 ч

Dependencies: FE-003

Description: Создать маршруты /login, /register, /tasks, /tasks/new и /tasks/:id. Неизвестный адрес показывает страницу 404 со ссылкой на задачи.

Acceptance Criteria: Все маршруты открываются; неизвестный путь показывает 404; переходы не перезагружают страницу.

## FE-005 Подготовить общие элементы интерфейса
Week: 2 · Epic: Основа интерфейса · Priority: High · Estimate: 3 ч

Dependencies: FE-004

Description: Сделать шапку, навигацию, кнопки и поля с label и местом для ошибки. Использовать простое оформление из прототипа без дополнительных функций.

Acceptance Criteria: Элементы повторно используются на страницах; активная ссылка выделена; поля доступны с клавиатуры.

## FE-006 Подготовить API клиент и демонстрационные данные
Week: 2 · Epic: Данные · Priority: High · Estimate: 3 ч

Dependencies: FE-003

Description: Создать Axios клиент с адресом API из VITE_API_URL. Отдельно подготовить демонстрационные ответы User и Task для работы без сервера. Task: id, title, subject, description, due_date, status; статусы planned, in_progress, completed.

Acceptance Criteria: Адрес не зашит в компоненты; .env.example не содержит секретов; демонстрационный режим включается явно; ошибки API передаются интерфейсу.

## FE-007 Сделать форму регистрации
Week: 2 · Epic: Авторизация · Priority: High · Estimate: 3 ч

Dependencies: FE-005, FE-006

Description: Добавить email и пароль, проверку обязательных полей и формата email. Отправлять POST /api/auth/register; серверные ограничения пароля согласовать с API.

Acceptance Criteria: Пустые поля не отправляются; повторный email показывает ошибку; при успехе открывается вход; при сбое введённый email сохраняется.

## FE-008 Сделать вход пользователя
Week: 2 · Epic: Авторизация · Priority: High · Estimate: 3 ч

Dependencies: FE-005, FE-006

Description: Добавить форму входа и POST /api/auth/login. Сохранить состояние сессии в auth slice, не выводить токены в сообщения или журнал. Формат токенов сверить с сервером.

Acceptance Criteria: Верные данные открывают /tasks; неверные дают понятную ошибку; повторный клик во время запроса не отправляет второй запрос.

## FE-009 Защитить страницы и добавить выход
Week: 3 · Epic: Авторизация · Priority: High · Estimate: 2 ч

Dependencies: FE-008

Description: Закрыть страницы задач для гостя. Обработать истечение сессии и POST /api/auth/logout; после выхода очистить auth и кэш задач.

Acceptance Criteria: Гость направляется на вход; после выхода список недоступен; ответ 401 завершает сессию и не показывает чужие или старые данные.

## FE-010 Показать список задач
Week: 3 · Epic: Задачи · Priority: High · Estimate: 3 ч

Dependencies: FE-005, FE-006, FE-009

Description: Получать GET /api/tasks. В карточке показать название, дисциплину, срок и статус; добавить переход к задаче и кнопку создания.

Acceptance Criteria: Отображаются данные ответа API; у каждой карточки стабильный id; кнопка создания ведёт на /tasks/new.

## FE-011 Добавить состояния списка
Week: 3 · Epic: Задачи · Priority: High · Estimate: 2 ч

Dependencies: FE-010

Description: Сделать состояния загрузки, отсутствия задач и ошибки. Для ошибки добавить повторный запрос, для пустого списка — переход к созданию.

Acceptance Criteria: Во время загрузки есть пояснение; пустой список не выглядит как ошибка; повтор запускает запрос; успешный ответ убирает сообщение об ошибке.

## FE-012 Сделать форму новой задачи
Week: 3 · Epic: Задачи · Priority: High · Estimate: 3 ч

Dependencies: FE-005, FE-010

Description: Создать поля title, subject, due_date и необязательное description. Название, дисциплина и срок обязательны; пробельный title считать пустым; добавить отмену.

Acceptance Criteria: Поля имеют подписи; ошибки видны рядом с полями; отмена возвращает к списку; неверные данные не отправляются.

## FE-013 Подключить сохранение новой задачи
Week: 4 · Epic: Задачи · Priority: High · Estimate: 2 ч

Dependencies: FE-006, FE-012

Description: Отправлять POST /api/tasks с данными формы и status=planned. После успеха обновить список; при ошибке сохранить ввод.

Acceptance Criteria: Новая задача появляется как «Запланирована»; повторный клик заблокирован до ответа; ошибка не показывает ложный успех.

## FE-014 Показать страницу задачи
Week: 4 · Epic: Задачи · Priority: High · Estimate: 2 ч

Dependencies: FE-010

Description: По /tasks/:id запрашивать GET /api/tasks/{id}. Показать все поля, возврат к списку и действия редактирования, удаления и изменения статуса.

Acceptance Criteria: Открывается нужная задача; загрузка и ошибка обработаны; 404 даёт сообщение «Задача не найдена» и ссылку на список.

## FE-015 Добавить редактирование задачи
Week: 4 · Epic: Задачи · Priority: High · Estimate: 3 ч

Dependencies: FE-012, FE-014

Description: Заполнить форму текущими значениями; отправлять PATCH /api/tasks/{id}. Сохранить проверки новой формы; отмена не изменяет данные.

Acceptance Criteria: После сохранения новые значения видны в карточке и списке; отмена оставляет старые данные; ошибка сохраняет ввод.

## FE-016 Добавить смену статуса
Week: 4 · Epic: Задачи · Priority: High · Estimate: 2 ч

Dependencies: FE-014

Description: Предлагать три статуса: Запланирована, В работе, Выполнена. Отправлять PATCH /api/tasks/{id}; разрешить возврат выполненной задачи в работу.

Acceptance Criteria: Каждый статус сохраняется и виден после повторного запроса; возврат в работу доступен; при ошибке остаётся подтверждённый сервером статус.

## FE-017 Добавить удаление с подтверждением
Week: 5 · Epic: Задачи · Priority: High · Estimate: 2 ч

Dependencies: FE-014

Description: Показать окно подтверждения с названием задачи, кнопками отмены и удаления. При подтверждении отправлять DELETE /api/tasks/{id}.

Acceptance Criteria: Отмена не отправляет DELETE; успех убирает задачу; ошибка оставляет задачу и показывает сообщение; фокус возвращается к доступному элементу.

## FE-018 Добавить поиск и фильтры
Week: 5 · Epic: Поиск и сроки · Priority: High · Estimate: 3 ч

Dependencies: FE-010

Description: Искать по названию без учёта регистра. Добавить фильтры дисциплины и статуса; все условия применять совместно к загруженным задачам. Добавить сброс.

Acceptance Criteria: Результаты соответствуют одновременно всем условиям; сброс возвращает весь список; нулевой результат показывает «Ничего не найдено».

## FE-019 Добавить сортировку и просрочку
Week: 5 · Epic: Поиск и сроки · Priority: High · Estimate: 2 ч

Dependencies: FE-010, FE-016

Description: Сортировать сроки от ближайших к дальним и наоборот. Для одинаковых дат использовать id. Отмечать незавершённую задачу с датой раньше сегодняшнего дня как просроченную; сравнивать календарные даты.

Acceptance Criteria: Вчерашняя незавершённая задача отмечена; сегодняшняя и выполненная не отмечены; оба направления сортировки работают без изменения данных.

Acceptance Criteria: Сообщения понятны; двойной клик не дублирует операции; после сбоя можно повторить действие без повторного заполнения.

## FE-022 Проверить интерфейс с реальным API
Week: 6 · Epic: Проверка · Priority: High · Estimate: 3 ч

Dependencies: FE-009, FE-013, FE-015, FE-016, FE-017, FE-018, FE-019

Description: Отключить демонстрационные данные и пройти регистрацию, вход, создание, изменение и удаление с готовым сервером. Проверить 400, 401, 404 и сетевой сбой; два пользователя не должны видеть задачи друг друга.

Acceptance Criteria: После обновления страницы данные сохраняются; ошибки отображаются; задачи двух аккаунтов разделены. При дефекте доступа завести отдельную задачу backend, не скрывать его только интерфейсом.
